# API v1 — image URL contract

External clients consume Excelsior card images directly from the CDN. This
document defines the contract so a client can construct image URLs from a
card payload without extra API calls.

## 1. Base URL

- **Production:** `https://cdn.excelsior.cards` (set via `APP_CDN_BASE`).
Resolves to the CloudFront distribution defined in
`[infra/cloudfront.tf](../../infra/cloudfront.tf)`. Always HTTPS after
Phase 0 (see `[OPS_TLS_AND_HTTPS.md](OPS_TLS_AND_HTTPS.md)`).
- **Local dev:** images are served by the Express static middleware under
`/src/resources/...`. `APP_CDN_BASE` is empty; clients should read
`window.APP_CDN_BASE` or `/js/app-config.js` to pick the right base.

When joining a base and a path, always strip trailing `/` from the base and
leading `/` from the path to avoid `https://cdn.net//src/...` which some
origins reject.

## 2. Path shape

All card images live under:

```
/src/resources/cards/images/<type>/<file>
```

Thumbnails live under:

```
/src/resources/cards/images/<type>/thumb/<file>
```

Where `<type>` is one of:

- `characters`
- `locations`
- `special`
- `missions`
- `events`
- `aspects`
- `advanced-universe`
- `teamwork`
- `ally-universe`
- `training`
- `basic-universe`
- `power`

`<file>` is the server-provided basename from the catalog payload. Clients
MUST NOT guess filenames from card IDs; always use the `image` / `imagePath`
field on the catalog DTO.

## 3. Thumbnail dimensions

Thumbnails are generated by
`[src/scripts/generateCardThumbnails.ts](../../src/scripts/generateCardThumbnails.ts)`.
The sizes are declared in `THUMB_CONFIGS` and currently target the
deck-selection and mobile DBV views. A matching CSS rule pins the display
size (see `[.cursorrules](../../.cursorrules)` "Image Pipeline"). If the
dimensions change, the CSS and this doc must change in the same PR.

## 4. Rotation and mutation

Image filenames are content-addressed by the card's underlying SKU, not by
timestamp. The server never rewrites an existing image under the same path.
Clients may cache image responses indefinitely (`max-age=31536000`). If an
image ever needs to change, the server-side mitigation is to give it a new
filename in the catalog payload.

## 5. Background images

Background images are NOT gitignored. They ship with the code and are synced
to S3 by the deploy workflow (`aws s3 sync src/resources/images/backgrounds/`).
Paths are returned by `GET /api/v1/dbv/deck-backgrounds`.

## 6. Missing / 404

If the catalog payload references a file that is missing from S3, the CDN
returns `404`. The most common cause is a thumbnail that was not generated
before the `sync-images` CI job ran. The app falls back to the teal-outlined
blank card slot described in the ".cursorrules" Image Pipeline section.

External clients SHOULD show a similar fallback rather than a broken-image
icon.
